# 雷系构筑核心重做 · 0.15.18

## 为什么调整

旧雷系只有雷丸能推动叠印，武器却不断把带印目标击杀。概率触发、冷却、飞行、重复命中同一目标形成多重门槛。余电虽然补上部分清怪伤害，却没有让传印和蓄雷产生不同打法。本轮改变触发与武器参与方式，不再只提高伤害倍率。

## 当前规则

- **命中触发可靠释放**：所有完整配方在命中冷却结束后，下一次武器命中必定释放，取消额外 30% 抽签。两秒基础冷却、专精、槽位和容量限制保留。它改变了随机数消耗路径，旧整局哈希不能用来声称战斗不变。
- **雷丸播种，武器充能**：武器实际扣血命中已有雷印的存活目标时增加一印；每目标间隔 0.5 秒，全局间隔 0.12 秒。雷杖连锁、环刃和炎炮持续伤害都通过同一入口，不能靠高频或同帧多目标瞬间叠满。武器不能凭空建立雷印，Buff、反伤不充能。武器充能不刷新剩余窗口，来源伤害仍取雷丸快照。
- **三印传印清群**：三印引爆主目标 120%，向附近 3 敌传两印，Lv.5 为 5 敌；死亡余电也向 3/5 个合格邻敌分发，每印放电 40%。传播不直接引爆、不刷新窗口、不连续继承；后续武器或雷丸命中才兑现下一次反应。
- **五印蓄雷打强敌**：雷丸释放优先 Boss、精英，再考虑已有雷印；无强敌时依然可打普通怪。雷丸直击叠两印，武器充一印；五印爆发 300%，Lv.5 为 350%，无引爆溅射。雷丸直接命中可续存九秒。死亡余电只转移一个目标，优先附近强敌。
- **跨槽冰霜导冷**：雷丸直接命中仍可从另一槽有效冰霜额外获得一印，每目标每秒一次；武器接触不会自行获得导冷加成。
- **致死与计伤**：武器本身致死时走死亡继承，不再对尸体进行充能和引爆伤害。非致死武器命中若触发雷印反应，反应可击杀目标，奖励只结算一次。死亡继承沿用每步 16 次搜索与雷印 200 目标上限；先保留继承状态再放电，不能递归炸穿怪群。
- **同槽环绕接续**：命中更可靠后，同槽环绕改为刷新寿命及新伤害快照，延续旋转相位和原目标接触冷却，不叠出多组环绕。火场保留铺路/区域战术，炉心沿用同处刷新；本轮没有把不同位置的火场强制合并。

完整配方、分支卡与紧凑说明已同步。雷印层数、引爆和传递继续复用原图集与有上限的反馈队列。

## 配对结果

标准探索，种子 1104/627，三武器 × 两雷系分支 × 普通/保命，改前后各 24 局。真实奖励、构筑选片、有效扣血账本，自动操作策略保持原样。保命模式不死亡；战斗变化导致随机序列分叉，样本不是显著性、真人难度或真机性能结论。

| 样本 | 改前引爆 | 改后引爆 | 改后普通怪 / 精英 / Boss |
|---|---:|---:|---|
| 普通 12 局 | 1 | 150 | 100 / 44 / 6 |
| 保命 12 局 | 26 | 429 | 282 / 73 / 74 |

种子 1104 普通样本：

| 武器 | 传印引爆 | 蓄雷引爆 |
|---|---|---|
| 雷杖 | 0 → 9（普通怪 5、精英 4） | 0 → 12（精英 6、Boss 6） |
| 炎炮 | 0 → 80（普通怪 75、精英 5） | 0 → 3（精英 3） |
| 环刃 | 0 → 13（普通怪 10、精英 3） | 0 → 3（精英 3） |

两种子的普通蓄雷样本引爆均发生在精英/Boss；传印主要在怪群中兑现。分工开始成立，但炎炮传印远高于另外两武器，仍需平衡。

普通通关仍为 1/12，改前是 627 炎炮蓄雷，改后为 1104 雷杖蓄雷（619.7 秒）；保命仍为 12/12。不能把引爆变多等同于胜率改善。例如普通 627 环刃蓄雷存活 499.5 → 374.6 秒；保命 1104 环刃蓄雷 Buff 占比 22.3 → 20.3%，虽然引爆 3 → 13。其他组合有效伤害占比多有增加，见[完整逐局对照](data/thunder-core-01518.json)。

另外以种子 1104 跑火冰三武器四分支，普通/保命各 12 局，共 24 局回归。保命 12/12 完成 Boss，普通 0/12 通关；这批没有额外配对基线，不用于评价难度改善。同槽环绕不叠加后需要重新校准冰系成长与风险回报，见[火冰记录](data/thunder-core-other-01518.json)。

## 验收与后续

核心验收是“普通战斗能够实际引爆、传印清群与蓄雷强敌有不同分工、三武器均可参与”。本轮实现了这些机制与样本验证；节奏是否足够爽快、触发是否清晰、难度是否合适仍需真人测试。下一步应评估炎炮传印优势、冰环接续后的收益、普通生存压力和控制效用，避免继续无差别提高倍率。

新增测试覆盖 30/60/120Hz 下武器充能限频、同帧多目标共享限制、持续伤害、来源快照与过期窗口、强敌优先、死亡群传上限、同槽冰环相位/接触冷却，以及真实 Game 的反应击杀与有效伤害归属。

最终验证：382 项测试通过；TypeScript 格式与差异空白检查通过。H5 四种手机尺寸的 Buff 面板/触摸检查、微信包浏览器兼容与触摸回归均通过；浏览器检查不代表真机帧率。`_wechat` 已重新生成，包大小 4,037,767 字节，保留本地 AppID。检查日志保存在本地 `artifacts/thunder-core-tests-final-01518.log`、`artifacts/thunder-core-h5-browser-01518.log` 与 `artifacts/thunder-core-wechat-browser-01518.log`。
