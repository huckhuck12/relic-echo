# 怪潮数量与性能测试报告

> 2026-10-29 / 0.7.1 更新：根据实际浏览器卡顿反馈，正常对局上限降为 240。新增三档画质、简化普通怪、减少地面纹理与装饰粒子、地面效果分层、危险预警置顶，以及深度排序分档。默认标准画质为 36 特效 / 16 数字 / 24 普通血条；精英血条不占普通预算。56 项自动检查通过。浏览器控制认证失败，备用 Edge 返回 `spawn EPERM`，没有新的真实 FPS 结论。以下 0.5 的 600 / 1000 只数据保留为历史逻辑测试，不能代表当前版本浏览器表现。

测试日期：2026-10-28。版本：0.5.0。

当前实测覆盖 Node.js 战斗逻辑和绘图命令生成，不含 LayaAir WebGL 执行、GPU、浏览器帧调度或真机性能。因此下文的毫秒不能直接换算成游戏 FPS。

## 数量调整

- 正常对局场上怪物上限由 240 提高至 600，约第 8 分钟达到该容量。实际存活数量取决于玩家清怪速度。
- 开局仍每批 1 只，3 分钟每批 4 只、5 分钟 7 只、7 分钟后 10 只。
- 大怪潮每次补入最多 80 只，间隔由 24 秒逐步缩短至 12 秒，继续混入精英、远程与冲锋。
- 1000 只仅用于超额压力测试，不作为正常对局数量上限。弹道上限仍是 240，掉落 170，特效 60。

## 测试环境与方法

- CPU：Intel(R) Core(TM) i5-9600KF CPU @ 3.70GHz；Node.js：v24.19.0。
- 随机种子固定为 20261028，分别测试 240 / 600 / 1000 只与三种满强化武器。
- 每种场景预热 60 步，再记录 300 步；固定逻辑步长 1/60 秒。敌人使用高生命维持数量，包含移动、分离、远程预警、弹幕、武器攻击与特效。
- 初始 208 发敌方弹道、170 个经验掉落；弹道持续按游戏规则消耗和生成，不保证每一步满弹道。
- 怪群逐步向玩家聚集，覆盖较密集的邻居查询；图形使用无实际绘制的替身。
- GC 前后堆内存差值仅反映短测保留内存，不构成长时间无泄漏的证明。单次压测受 JIT、GC 和系统后台活动影响。

## 已实施的优化

- 怪物分离查询最多返回 8 个邻居，找到后即停止；避免先收集整个密集怪群再截取。
- 攻击锁定与雷电弹射改为单次扫描最近目标，移除对整组候选的排序。
- 空间网格复用单元数组，伤害文字复用有限对象池，减少临时分配。
- 屏幕外角色、弹道和掉落跳过绘图更新，仍参与战斗计算；重新进入视野后恢复。
- 普通怪血条最多绘制 48 条，精英血条独立保留；蓄力预警继续绘制，避免漏掉从屏幕外射入的警示线。
- 圆环使用预计算顶点，减少持续燃烧区域和特效的三角函数计算。

## WebGL 验证状态与复现

当前托管环境拒绝启动 Edge 子进程（spawn EPERM），尚未获得真实浏览器 FPS、GPU 耗时或手机温升数据；没有用逻辑替身数据填充这些指标。

```powershell
npm run perf
```

运行本地服务后，访问 http://localhost:8080/bench/index.html 。该页面使用真实 LayaAir、WebGL 和 HUD，依次测试九种场景，采集逻辑耗时、命令生成耗时、Laya 舞台循环耗时及 rAF 帧间隔，并提供 JSON 下载。舞台循环耗时包含 CPU 提交工作，不等同于纯 GPU 耗时。测试期间应保持标签页前台，约一分钟完成，低性能设备可能更久。

也可在允许启动浏览器的本地终端运行：

```powershell
npm run perf:browser
```

此自动脚本以隐藏的 headless Edge 运行，默认视口参数为 1280×720，结果记录实际视口、DPR 和 WebGL 渲染器；headless 结果仍不代表手机或可见窗口体验。可用 PERF_BROWSER 指定浏览器路径。

## 当前结论

逻辑压测支持将正常对局上限提高到 600。1000 只作为额外压力档保留。正式判断能否稳定 60 FPS，需要完成真实浏览器渲染测试与目标手机验收。
