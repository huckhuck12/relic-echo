# 开发与 GitHub Pages 发布

## 本地开发

需要 Node.js 22 及以上，推荐与 CI 相同的 Node.js 24。项目锁定 TypeScript 5.0.2，安装后不依赖全局 tsc。

```sh
npm ci
npm run dev
```

游戏入口为 `http://localhost:8080/`。不要通过双击 index.html 使用 file:// 打开，浏览器 ES 模块需要 HTTP/HTTPS。

| 命令 | 用途 |
|---|---|
| `npm run build` | 清理 dist，使用锁定编译器构建 |
| `npm test` | 构建并运行逻辑、UI 节点和静态发布验证 |
| `npm run format` | 用锁定 TypeScript 打印器统一 src 格式，保留注释 |
| `npm run format:check` | 检查源码格式，供提交前和 CI 使用 |
| `npm run build:pages` | 构建独立的 `_site` 静态游戏目录 |
| `npm run preview:pages -- --port 8081` | 在 `/relic-echo/` 子路径模拟 Pages 部署 |

## 发布到 GitHub Pages

1. 将项目源文件提交到自己的 GitHub 仓库，包含 `.github`、`package.json`、`package-lock.json`、`src`、`scripts`、`tests`、`index.html` 和 `vendor`。Laya 引擎已保存在 vendor，无需运行时访问 CDN。dist、_site、缓存和本地验收产物由 .gitignore 排除。
2. 在仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
3. 向 `main` 或 `master` 推送提交；也可在 **Actions → Build and deploy game to GitHub Pages → Run workflow** 手动运行。若第一次推送时尚未启用 Pages，启用后重新运行工作流。
4. 等待 build 和 deploy 两个任务成功。地址显示在部署任务的 github-pages 环境中，通常是 `https://你的用户名.github.io/仓库名/`。账号主页仓库也可直接运行在域名根路径。

工作流执行 `npm ci → 格式检查 → 全套测试 → 静态构建 → 上传 _site → 部署`。入口、引擎和编译后的所有 ES 模块使用相对路径，不需要把源码中的路径替换成仓库名。若使用其他默认分支，修改 `.github/workflows/pages.yml` 的 push.branches，或手动触发工作流。

当前工作区没有 `.git` 和 GitHub 远端；这里提供了部署代码和可验证的发布包，并未创建仓库、推送提交或执行线上部署。实际 GitHub Actions 运行结果仍需在目标仓库检查。

## 本地核对发布包

```sh
npm run build:pages
npm run preview:pages -- --port 8081
```

访问 `http://localhost:8081/relic-echo/`。这模拟仓库站点的路径层级，确认游戏能开局、选卡、装配 Buff 和重开。`_site` 可整体托管在任意支持静态文件的服务器上；不需要 Node.js 后端。

Pages 包只包含入口、运行时 JS、vendor 引擎和 `.nojekyll`。开发验收页仍通过普通本地服务 `/bench/` 使用。发布打包会清理旧 `_site`，编译会清理旧 dist，避免删除源码后继续发布过期 JS。

源码已按功能分目录，编译和发布包保留相同层级，例如 `src/game/game.ts → dist/game/game.js`。Pages 打包和格式检查会递归扫描子目录，开发预览与测试也使用新路径；不要将 dist 的模块重新平铺或手动移动。`index.html` 仍只引用 `dist/main.js`。

自动验证会沿入口脚本递归检查所有 ES 模块，核对文件名大小写，并分别在根路径和仓库子路径通过 HTTP 加载。它验证的是部署资源完整性，不代表浏览器 WebGL/GPU、触屏交互或帧率已经实测。

## 维护约定

- 模拟先更新、显示后读取；显示模块不改伤害、冷却和随机数。
- 配置按领域分开，见[代码结构与维护说明](代码结构与维护说明.md)顶部的配置索引。
- BuffRuntime 保持兼容导出，内部新增模块直接依赖 buff-config/buff-types，避免相互导入运行时。
- 重构时保留命中/奖励/随机数调用顺序；不要把新玩法造成的差异覆盖进旧回归基线。
- 新增网页资源使用相对 URL，并运行 Pages 集成验证，特别检查 Linux 上的文件名大小写。
