# 遗迹学徒：选定方向与制作约束

用户已选择 B。身份和服装以 `output/imagegen/hero-b-ruin-apprentice-v2.png` 为准：栗棕偏分发、约三头身、紫色短学者外衣、米色围巾、琥珀扣、腰侧笔记本、棕色短靴，以及小型悬浮淡紫符晶。保留克制的布料与皮革笔触；缩到手机尺寸时，优先读出围巾、紫衣和发型。

## 当前制作阶段

0.12.1 已接入透明角色身体图集。此前的四视图和三阶段施法概念样张继续作为参考；游戏使用另行生成并清理、切片、对齐后的动作资源。

## 接入现有项目的技术约束

- 引擎为 LayaAir 2.0.2，屏幕空间 2.5D；角色原点是脚底 `(0,0)`，当前角色约 80 逻辑像素高。
- 保留当前八向约定：右、右下、下、左下、左、左上、上、右上。正侧背样张用于锁定形象，不能宣称覆盖现有八向动画。
- 现有 PlayerAtlas 为每个当前装备组合缓存 128 姿态：八向各四个行走姿态和十二个施法姿态。新精灵需要明确映射，不能只用单张正面图左右翻转代替八向。
- 现有武器包括 storm、flame、blade。符晶是本次动作样张的视觉主题；后续仍需针对各武器校准握把、施法姿态和挂点，不应改动技能伤害、射击方向与碰撞逻辑。
- 身体与装备拆分方案确定后，再决定固定服装的精灵主体和可换装叠层。不要为所有装备组合预生成独立大图集。
- 目标为单个常驻共享图集、按帧切片；不在每帧上传纹理。先以 1024×1024 RGBA（4 MiB）做预算目标，最终按实际帧尺寸验证，禁止未经测量声称达标。
- Web 与微信小游戏构建均打包 `assets/`，通过引擎的图片创建接口加载本地资源；失败时保留原程序角色。异步完成会使角色缓存失效，站立时也能更新。

## 验收

在真实草地背景上检查约 80px 角色轮廓、头发和围巾边缘；检查前后转向时服装一致、脚底稳定、施法手与技能起点对应。确认 alpha 真透明、无纸色边缘、无错位和裁切。随后再做 H5、微信适配与真机性能验证。

概念样张不作为生产资产。0.12.1 将经过规范化的身体帧与现有装备挂件合成后用于运行时。

## 0.12.1 运行时资源

通过同一 CLI 的 edit 模式、`gpt-image-2`、high、请求 1536×2048，以选定 B 和对应转面/动作样张为参考，生成：

- `output/imagegen/hero-b-walk-source.png`：实际 1122×1402，四列五行，20 帧。
- `output/imagegen/hero-b-cast-source.png`：实际 971×1619，三列五行，15 帧。
- 对应完整提示词为 `hero-b-walk-sheet-prompt.txt` 与 `hero-b-cast-sheet-prompt.txt`。

独立方向为右、右下、下、上、右上，镜像补齐左下、左、左上。镜像方向的非对称服装细节也会反转，这是本轮节省素材制作量的取舍。不是八个方向独立绘制。

接口返回了带 alpha 的图，但夹杂饱和红/黄/洋红边缘碎片。`scripts/build-hero-art.ps1` 调用 `HeroAtlasBuilder.cs`，剔除残留色、保留单个主体连通域，逐行按共享尺度规范化，并按脚部中心对齐。输出 `assets/hero/ruin-apprentice.png`（1024×1024 RGBA，56 帧）与 JSON 元数据。每格 96×128，脚底 `(48,124)`，每逻辑像素 1.5 个源像素，人物高约 80 逻辑像素。

Alpha 检查：810498 个全透明像素、203220 个 alpha≥240 的像素、0 个命中残留色阈值的像素。离线草地底检查图为 `output/imagegen/hero-b-atlas-preview.png`。清理阈值与连通域检查只适用于这两张已经目检的源图，不是通用自动验收工具。

PlayerAtlas 将身体与头饰、护甲附件、背饰、武器和品质标记合成到当前装备组合的 128 姿态缓存。四个行走帧循环；十二个施法时间片映射到蓄势、释放、收势三个身体关键姿态，武器继续使用原有十二时间片的变换。普通护甲仍以紫衣为基础，重甲肩片、能量核心等叠层保留；本轮没有为各护甲重新绘制整套衣服。当前武器轮廓与身体动作仍可继续细化，尤其是双手炎炮。

身体源图只作为共享解码图片保留，约 4 MiB CPU 像素，不单独上传 GPU。场景合成页仍限制为 8 MiB，换装销毁旧页；静态装备预览只生成一个姿态，最多 64 KiB，并随节点销毁。场景纹理统计不包含解码图片和引擎其他内存，不能当作整个微信进程内存。

已通过 219 项测试（含加载延迟、加载失败、资源尺寸、帧索引、缓存替换、静态预览销毁与打包资源检查）。真实 Laya/WebGL 的 393×852、852×393 与 1280×720 入口均确认加载新角色、战斗和装备预览可用；当时场景纹理统计 14 MiB。未将浏览器表现等同于 iPhone Air 真机性能或闪退验证。

微信打包后的真实引擎与 mock SDK 检查也通过，图片由包内路径加载。固定场景 235 怪物、208 弹道、150 掉落的 DrawCall 仍为 26，与 0.12.0 的同场景记录一致。构建总文件大小为 2381184 字节。验证报告保存在 `docs/render-results-0121.json`，截图为 `docs/art/hero-b-ingame.png`、`docs/art/hero-b-mobile.png`。这些结果不代表手机原生 GPU 或长时间稳定性。
