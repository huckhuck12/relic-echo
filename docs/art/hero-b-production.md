# 遗迹学徒：选定方向与制作约束

用户已选择 B。身份和服装以 `output/imagegen/hero-b-ruin-apprentice-v2.png` 为准：栗棕偏分发、约三头身、紫色短学者外衣、米色围巾、琥珀扣、腰侧笔记本、棕色短靴，以及小型悬浮淡紫符晶。保留克制的布料与皮革笔触；缩到手机尺寸时，优先读出围巾、紫衣和发型。

## 当前制作阶段

先制作四视图转面和三阶段施法关键姿态，检验形象一致性。这些是概念样张，不能把整张带纸背景的图直接当作角色精灵。生产帧必须再统一视角、分离背景、对齐脚底、检查边缘和动作衔接。

## 接入现有项目的技术约束

- 引擎为 LayaAir 2.0.2，屏幕空间 2.5D；角色原点是脚底 `(0,0)`，当前角色约 80 逻辑像素高。
- 保留当前八向约定：右、右下、下、左下、左、左上、上、右上。正侧背样张用于锁定形象，不能宣称覆盖现有八向动画。
- 现有 PlayerAtlas 为每个当前装备组合缓存 128 姿态：八向各四个行走姿态和十二个施法姿态。新精灵需要明确映射，不能只用单张正面图左右翻转代替八向。
- 现有武器包括 storm、flame、blade。符晶是本次动作样张的视觉主题；后续仍需针对各武器校准握把、施法姿态和挂点，不应改动技能伤害、射击方向与碰撞逻辑。
- 身体与装备拆分方案确定后，再决定固定服装的精灵主体和可换装叠层。不要为所有装备组合预生成独立大图集。
- 目标为单个常驻共享图集、按帧切片；不在每帧上传纹理。先以 1024×1024 RGBA（4 MiB）做预算目标，最终按实际帧尺寸验证，禁止未经测量声称达标。
- Web 与微信小游戏都需要打包生产图片资源；当前构建没有这组概念图的运行时加载流程。接入时需要同时处理打包、预加载、失败回退和资源释放。

## 验收

在真实草地背景上检查约 80px 角色轮廓、头发和围巾边缘；检查前后转向时服装一致、脚底稳定、施法手与技能起点对应。确认 alpha 真透明、无纸色边缘、无错位和裁切。随后再做 H5、微信适配与真机性能验证。

本阶段不改变游戏运行时，不将概念样张标为生产资产。
