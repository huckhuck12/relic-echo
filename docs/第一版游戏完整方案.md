# 《遗迹回响》第一版游戏方案

> 状态：开发前设计稿；项目名暂定。目标是先交付一款可完整游玩、具备可见换装的 2.5D 肉鸽生存游戏。
> 技术方向：TypeScript + LayaAir 3.x，2D 分层图形模拟 2.5D。具体引擎小版本在创建工程时锁定。
> 资源前提：无现成美术资源，第一版使用程序生成的几何角色、装备、场景和特效。

## 1. 产品目标与边界

玩家在遗迹竞技场中移动、冲刺、自动攻击，通过升级选择与装备替换形成战斗构筑，在 10 分钟内击败最终 Boss。

第一版必须验证三个体验：

1. 移动、攻击、命中和闪避有清晰反馈。
2. 升级与装备能改变打法，至少形成三种可区分的构筑。
3. 装备穿换立即体现在角色身上，战斗过程中也能识别武器和轮廓变化。

| 项目 | 第一版范围 |
|---|---|
| 平台 | 桌面浏览器和手机浏览器，横屏；微信小游戏后续适配 |
| 模式 | 单人本地战斗，无联网 |
| 时长 | 每局 10 分钟，成功击败 Boss 或角色死亡后结算 |
| 角色 | 1 个几何风格角色 |
| 地图 | 1 张固定竞技场 |
| 敌人 | 3 类普通怪、1 类精英、1 个 Boss |
| 武器 | 3 种，每种有明确攻击方式和外观 |
| 装备 | 武器、头饰、护甲、背饰，共 4 个槽位、12 件基础装备 |
| 成长 | 局内升级三选一、局内装备掉落；局外保存设置和战绩 |
| 美术 | 程序图形、少量程序生成纹理；不依赖外部图片或 AI 服务 |

第一版暂不包含随机迷宫、任务剧情、联机、宠物、锻造、装备强化、装备交易、仓库、随机词条和商业化。装备局内获得，结算后重置，不跨局积累数值。

## 2. 核心玩法循环

```text
进入游戏 → 选择初始武器 → 开始战斗
                            ↓
移动与冲刺 → 自动攻击 → 击杀 → 拾取经验 → 升级三选一
                  ↓
             掉落装备 → 对比属性与外观 → 装备或分解
                  ↓
          精英事件 → 完成构筑 → 最终 Boss → 结算 → 重开
```

升级、查看装备和暂停菜单均暂停整个战斗模拟，包括怪物、弹道、持续伤害、刷新计时和生存时钟。关闭弹窗后恢复，避免手机操作时受到不公平伤害。

## 3. 操作与战斗规则

### 3.1 操作

| 动作 | 电脑 | 手机 |
|---|---|---|
| 移动 | WASD / 方向键 | 左侧虚拟摇杆 |
| 冲刺 | 空格 | 右下冲刺按钮 |
| 攻击 | 自动 | 自动 |
| 查看角色装备 | E / 界面按钮 | 装备按钮 |
| 暂停 | Esc / 界面按钮 | 暂停按钮 |

角色自动攻击有效范围内最近的敌人。没有目标时停止发射；近战攻击以目标方向为准。角色朝向优先指向当前攻击目标，无目标时跟随移动方向。

### 3.2 初始数值

以下为可调初值，不视为最终平衡结果。

| 属性 | 初值 |
|---|---:|
| 生命 | 100 |
| 地面移动速度 | 220 逻辑单位 / 秒 |
| 暴击率 / 暴击伤害 | 5% / 150% |
| 冲刺距离 / 持续时间 | 150 逻辑单位 / 0.18 秒 |
| 冲刺冷却 / 无敌时间 | 3 秒 / 冲刺全程 |
| 受伤无敌时间 | 0.5 秒 |
| 经验拾取半径 | 70 逻辑单位 |

冲刺路径检测场景边界与实体障碍，不能穿墙；可以穿过敌人。敌人不会把玩家卡住，接触伤害受受伤无敌时间限制。

### 3.3 伤害与属性

```text
基础命中伤害 = 武器基础伤害 × (1 + 通用伤害加成 + 对应类型伤害加成)
暴击伤害 = 基础命中伤害 × 暴击伤害倍率
最终伤害 = max(1, 四舍五入(暴击后伤害 × (1 - 减伤率)))
最终攻击间隔 = 武器基础间隔 / (1 + 攻速加成)
```

同类百分比加成相加。第一版玩家减伤上限 60%、移速加成上限 50%、攻速加成上限 100%。灼烧和连锁伤害不暴击，也不再次触发命中类效果，防止无限触发。

击杀反馈包括短促闪白、轻微击退、死亡碎片与经验晶石；屏幕震动可在设置中关闭。Boss 关键攻击使用地面范围预警。

## 4. 地图与 10 分钟节奏

地图采用固定菱形视觉竞技场，逻辑空间为约 2400 × 2400 单位的方形地面。相机跟随玩家并限制边界。地面采用明暗交替的斜视网格，布置少量立柱、矮墙与遗迹装饰，中心区保持通畅。

可碰撞障碍使用简单地面包围形状；纯装饰不参与碰撞。高大遮挡物在玩家进入后方时降低透明度，保证角色可见。

| 时间 | 内容与目的 |
|---|---|
| 0:00—1:00 | 少量追击怪，熟悉移动、攻击和第一次升级 |
| 1:00—3:00 | 引入远程怪；约 2:00 第一次精英事件 |
| 3:00—5:00 | 引入冲锋怪；约 4:00 第二次精英事件 |
| 5:00—7:00 | 混合怪群；约 6:00 第三次精英事件 |
| 7:00—9:00 | 怪潮增强；约 8:00 第四次精英事件 |
| 9:00 | 最终 Boss 登场，清除普通怪及其弹道，停止普通刷怪 |
| 9:00—10:00 | Boss 战；击败立即胜利，10:00 尚未击败则本局失败 |

精英事件以击杀奖励为主，不强制玩家停在指定位置。普通敌人从镜头外地图内的有效位置出现，不在玩家附近突然生成。刷怪数量受性能预算约束，到达上限后推迟刷新，避免无限堆积。

## 5. 敌人与 Boss

| 敌人 | 行为 | 外观识别 | 对策 |
|---|---|---|---|
| 游荡者 | 持续接近，接触伤害 | 红色圆形主体 | 拉开距离、群体清理 |
| 投射者 | 中距离停留，定期发射慢速弹 | 紫色菱形与眼睛 | 侧向移动、优先击杀 |
| 冲锋者 | 蓄力后沿锁定方向冲刺 | 橙色三角轮廓 | 观察直线预警，横向闪避 |
| 遗迹守卫·精英 | 大体型追击，周期释放环形弹幕 | 强化外框、地面精英标记 | 利用间隙接近或绕行 |
| 最终 Boss·遗迹核心 | 在追击、扇形弹幕与范围砸地之间切换 | 大型多层核心、独立血条 | 看预警、留冲刺、持续输出 |

Boss 低于 50% 生命进入第二阶段：提高攻击频率，并在两次攻击之间缩短停顿。每次砸地预警至少保留 0.7 秒；不能出现无法躲避的连续范围覆盖。

生命、伤害、速度、冷却和刷怪曲线全部配置化，先以普通攻击击杀早期小怪约 2—4 次为调参起点。

## 6. 升级与流派

经验自动靠近拾取。初始升级经验需求为 10，此后每级需求暂定为 `10 + 6 × (当前等级 - 1)`；通过掉落量调整，使完整一局大约出现 15—20 次升级。

每次升级暂停战斗，展示 3 个不同选项。达到等级上限的强化不再出现；专属强化仅在持有对应武器时进入候选池。切换武器后，已选专属强化保留记录，在重新装备该武器时重新生效。

### 6.1 通用强化

| 强化 | 每级效果 | 上限 |
|---|---|---:|
| 力量 | 通用伤害 +10% | 5 |
| 急速 | 攻速 +8% | 5 |
| 体魄 | 最大生命 +20，当前生命同时 +20 | 3 |
| 轻盈 | 移速 +8% | 3 |
| 精准 | 暴击率 +5 个百分点 | 3 |
| 磁力 | 拾取半径 +25% | 3 |

### 6.2 武器专属强化

| 流派 | 武器 | 专属强化，每项最高 2 级 | 形成的打法 |
|---|---|---|---|
| 雷电 | 雷杖 | 连锁目标每级 +1；每级降低弹射伤害衰减 10 个百分点 | 自动瞄准、清理密集怪群 |
| 火焰 | 炎炮 | 每级增加灼烧每秒基础伤害 3；燃烧地面每级增加持续时间 1 秒 | 引导敌人经过持续伤害区域 |
| 飞刃 | 环刃 | 环绕飞刃每级 +1；环绕半径每级 +15% | 靠近怪群并沿边缘走位 |

武器初始就带有流派特征：雷杖默认弹射一次，炎炮命中附带灼烧和小块燃烧地面，环刃默认两把飞刃环绕。通过配置限制同一敌人被环刃连续命中的频率。

候选不足三个时使用未满级通用强化补齐；所有强化满级后提供恢复 30% 最大生命的选项，满血时转换为结算分数。

## 7. 装备系统

### 7.1 基本规则

装备系统纳入第一版，并且每个槽位都有可见外观。

- 槽位：武器、头饰、护甲、背饰；每个槽位装备 1 件。
- 开局选择一把基础武器，其他槽位为空。角色仍有完整基础身体外观。
- 装备固定效果，不做随机词条；同一基础装备最多存在普通、精良、稀有三个品质。
- 品质加成只提高数值，不追加技能规则。外观同时通过局部装饰和品质颜色反馈。
- 装备没有等级、耐久、重量、职业限制或套装门槛。
- 没有背包囤积。拾取后选择装备或分解；换下的旧装备立即分解，避免反复落地和拾取。
- 分解转为经验晶石，普通 / 精良 / 稀有暂定为 5 / 10 / 20 点经验。

### 7.2 第一版装备表

数值均为普通品质初值；武器伤害与间隔需要与敌人生命共同调优。

| 槽位 | 装备 | 效果 | 角色上的可见变化 |
|---|---|---|---|
| 武器 | 雷杖 | 基础伤害 16，间隔 0.7 秒，弹射 1 次，弹射伤害递减 30% | 手持蓝色长杖与发光杖头 |
| 武器 | 炎炮 | 基础伤害 22，间隔 1 秒；灼烧基础 4/秒、持续 3 秒 | 手持红橙色粗短炮管 |
| 武器 | 环刃 | 单次基础伤害 10，默认 2 把环刃，同目标命中间隔至少 0.35 秒 | 手腕刃环与实际环绕飞刃 |
| 头饰 | 战术目镜 | 暴击率 +8 个百分点 | 横向黄色发光镜片 |
| 头饰 | 术士兜帽 | 元素伤害 +12%，适用于雷电、火焰 | 紫色尖顶兜帽，露出脸部 |
| 头饰 | 守卫头盔 | 最大生命 +25 | 灰白色盔壳与额部护片 |
| 护甲 | 轻型战衣 | 移速 +12% | 青色窄肩胸甲 |
| 护甲 | 重型胸甲 | 减伤 +15 个百分点，移速 -5% | 宽肩、厚重胸甲，轮廓加宽 |
| 护甲 | 能量外衣 | 通用伤害 +12% | 紫色胸口核心与能量边线 |
| 背饰 | 疾行披风 | 冲刺冷却降低 20% | 短披风，移动时轻摆 |
| 背饰 | 荆棘背架 | 受伤时对半径 100 内敌人造成基础伤害 20，冷却 1 秒 | 两侧可见的棘刺背架 |
| 背饰 | 聚能背包 | 拾取半径 +40% | 圆形背包与顶部天线 |

炎炮灼烧同源刷新持续时间、不无限叠层；燃烧地面基础持续 2 秒，同一来源重叠区域不会重复造成多份伤害。环刃属于物理伤害。装备特殊触发同样遵循“不递归触发”的规则。

### 7.3 品质规则

| 品质 | 数值倍率 | 外观提示 |
|---|---:|---|
| 普通 | 1.0 | 基础结构和细边线 |
| 精良 | 1.2 | 青色品质嵌件、额外几何纹饰 |
| 稀有 | 1.4 | 金色品质嵌件、少量发光点 |

倍率作用于正向数值属性与武器基础伤害；攻击间隔、飞刃数量、弹射次数、负面移速、触发冷却和持续时间不随品质改变。百分比减冷却以加成值乘倍率，例如 20% → 24% → 28%。

主色仍用于识别装备类别，品质色只用于局部嵌件和 UI 边框，避免高品质把所有武器染成同一种颜色。

### 7.4 掉落与选择

- 普通敌人暂定 1% 概率掉落装备，并设置 30 秒全局掉落冷却；表现测试后调整。
- 四次精英事件各保证掉落 1 件装备。
- 第一次精英优先从未装备的非武器槽位中抽取。
- 掉落装备在接近玩家时触发对比弹窗，并暂停战斗；同一时刻只处理一件。
- 对比界面提供“装备”和“分解”两个动作，不额外嵌套确认。
- 同一装备、同一品质的重复件自动分解，并显示简短提示。
- 默认掉落权重为普通 70%、精良 25%、稀有 5%；6 分钟后改为 45%、40%、15%。

对比界面展示名称、槽位、品质、完整效果、数值增减和前后角色预览。比较武器时展示伤害、攻击方式与专属强化是否生效，不使用单一“战力值”判定优劣。

最大生命装备穿上后增加最大生命，当前生命保持原值；卸下时把当前生命限制在新上限内，不通过反复换装获得治疗。升级的体魄按独立规则增加当前生命。

## 8. 可见换装：角色必须真正穿上装备

### 8.1 外观目标

换装同时更新战斗属性与角色外观。武器必须改变模型轮廓和攻击表现；头饰、护甲、背饰必须有独立可见部件，不能只更换装备栏图标或角色颜色。

第一版角色采用大头短身、机械魔法风格，基础身体包含头、躯干、双手、双脚和椭圆地面阴影。装备使用几何形状组合，保证无资源也能形成完整角色。

初始建议：逻辑参考分辨率 1280 × 720，角色屏幕高度约 64—80 像素，装备最小辨识部件不小于 4 像素；这些尺寸是原型视觉调优起点。

### 8.2 分层与挂点

```text
角色地面根节点（用于移动、碰撞和场景深度排序）
├─ 地面阴影
└─ 角色视觉根节点（用于走路起伏、受击与跳跃偏移）
   ├─ 后侧装备层：披风、背包、背架
   ├─ 后侧手臂 / 武器挂点
   ├─ 双脚与基础躯干
   ├─ 护甲层
   ├─ 头部与头饰层
   └─ 前侧手臂 / 武器挂点
```

头饰挂在头部，护甲挂在躯干，背饰挂在背部，武器挂在持握手。装备继承角色动作，不各自漂浮。火炮弹道从炮口挂点发出，雷电从杖头发出。

角色采用前左、前右、后左、后右四个视觉方向。左右对称部件允许镜像；前后方向通过脸部显隐、装备前后层顺序和简化轮廓变化区分。朝后时背饰显示在身体前层，武器按持握侧切换前后顺序。

禁止对整个角色简单做全方向镜像来代替前后换向，否则背包和头饰会产生穿帮。第一版不要求逐帧手绘动画，采用步伐摆动、身体起伏、手部旋转与披风轻摆。

### 8.3 换装反馈

1. 在装备对比界面，左右显示当前角色与穿上候选装备的角色，姿态和朝向保持一致。
2. 点击装备后，同一游戏更新中提交属性与外观，再恢复战斗，避免状态不同步。
3. 角色新部件短暂高亮约 0.25 秒，装备栏同步刷新。
4. 角色面板提供前后预览切换，背饰可被清晰查看。
5. 移动、冲刺、受击、死亡都使用当前装备组合；重开时清空上一局外观状态。

环绕飞刃属于真实战斗对象，预览中使用纯视觉副本，不能发射弹道或触发伤害。暂停预览使用独立的 UI 动画时钟。

### 8.4 美术替换接口

每件装备通过 `visualId` 关联外观定义，外观配置包含挂点、方向变体、层级、偏移、缩放和品质装饰。第一版由程序图形绘制器生成；后续可以换成图集或骨骼附件，装备属性与掉落逻辑无需随之重写。

所有图形避免每帧重绘；优先在初始化和换装时构建或缓存，逐帧只更新位置、旋转、透明度。缓存纹理必须共享或及时释放，不能每次打开预览都新增一套永久纹理。

## 9. 界面与完整流程

| 界面 | 必要内容 |
|---|---|
| 标题页 | 开始、操作说明、设置、最近战绩 |
| 初始武器选择 | 三把武器、攻击说明、角色持握预览 |
| 战斗 HUD | 生命、经验、等级、时间、击杀、冲刺冷却、装备入口 |
| 升级弹窗 | 三个选项、当前等级与变化效果 |
| 装备对比 | 当前/候选属性、角色穿戴预览、装备/分解 |
| 角色面板 | 四槽装备、汇总属性、角色前后预览 |
| 暂停菜单 | 继续、设置、结束本局 |
| 结算页 | 胜负、时长、击杀、等级、伤害、最终装备、再次挑战 |

横屏手机 HUD 避开摇杆与冲刺触控区，并适配安全区域。竖屏时展示旋转提示，不强行缩小横屏界面。攻击预警和敌我弹道应兼顾形状、明暗与颜色区分。

连续触发升级与装备时，按进入队列顺序逐个处理；暂停状态由统一管理器维护，不能关闭一个弹窗就错误恢复仍有其他弹窗的战斗。

## 10. 技术实现方案

### 10.1 坐标、深度与碰撞

逻辑世界使用二维地面坐标 `(x, y)`，移动、距离、攻击范围、寻路和碰撞都在该平面计算。显示采用斜视投影，初始公式：

```text
screenX = (x - y) × 0.7071
screenY = (x + y) × 0.3536 - height
depth = x + y
```

屏幕方向输入需通过逆投影转回地面移动向量后归一化，保证按右键在画面中向右走，且斜向不会更快。相机、掉落物、瞄准方向与碰撞调试层使用同一坐标转换工具。

场景对象按地面脚底 `depth` 排序，跳跃和受击上浮不改变地面深度。阴影保留在地面层；飞行弹道依据地面位置排序，并单独管理高度。大体积障碍拆分底座与遮挡部分，避免整张图排序错误。

### 10.2 系统职责

| 模块 | 职责 |
|---|---|
| GameFlow | 标题、选择、战斗、结算状态切换 |
| BattleClock / PauseManager | 战斗时间、暂停引用、弹窗队列 |
| InputController | 键盘、触摸、冲刺输入与输入坐标转换 |
| PlayerController | 移动、生命、无敌、冲刺 |
| CombatSystem | 索敌、伤害、暴击、状态效果、触发限制 |
| EnemySystem / SpawnDirector | 敌人行为、空间查询与阶段刷怪 |
| ExperienceSystem / UpgradeSystem | 经验、升级和候选抽取 |
| EquipmentSystem / StatResolver | 装备替换、分解与完整属性重算 |
| AppearanceController | 挂点、朝向、装备部件和预览 |
| DropSystem | 经验、治疗与装备掉落、拾取队列 |
| UI / Audio / Save | 展示、声音、设置和本地战绩 |

采用清晰的实体数据与系统更新结构即可，不把完整 ECS 框架作为开工前提。换装后从基础属性、升级记录和当前装备重算最终属性，避免反复加减产生误差。

### 10.3 建议目录

```text
src/
  core/          # 状态、时钟、事件、对象池、坐标工具
  config/        # 武器、装备、强化、敌人、波次配置
  battle/        # 战斗、伤害、弹道、状态效果、空间网格
  player/        # 玩家、装备、属性、分层外观
  enemies/       # 普通敌人、精英、Boss
  world/         # 地图、相机、障碍、掉落
  ui/            # HUD、升级、装备对比、结算
  visuals/       # 程序图形、装备绘制、特效
  services/      # 存档、音效、设置
```

### 10.4 关键数据约定

装备配置至少包含：`id`、`slot`、`name`、`visualId`、`baseStats`、`effectId`、`weaponId`（仅武器）。运行时装备实例保存基础装备 ID 与品质；不复制和修改原始配置。

外观配置至少包含：`visualId`、`anchor`、`directionVariants`、`layerByDirection`、`offset`、`scale`、`qualityDecorations`。属性、战斗效果与渲染配置分别维护，以稳定 ID 关联。

战斗采用固定模拟步长并限制单帧补算次数；渲染独立刷新。页面失焦或浏览器切后台时自动暂停，返回后由玩家确认继续，不结算离线战斗。

## 11. 资源与声音计划

| 类别 | 第一版产出方式 |
|---|---|
| 角色与装备 | LayaAir 图形节点绘制，按方向分层组合 |
| 怪物和 Boss | 几何轮廓、颜色与动作区分 |
| 地面 | 少量共享程序纹理与网格，不为每块地砖创建复杂对象 |
| 技能与掉落 | 共享纹理、图形和受控数量粒子 |
| UI 图标 | 从对应装备外观生成简化图标，复用同一识别特征 |
| 音效 | 本地生成短促音效：攻击、命中、受伤、升级、换装、胜负 |
| 背景音乐 | 非首版验收必需；有统一可用素材后补充 |

音频在用户首次点击后初始化，处理浏览器自动播放限制。控制同时播放音效数量，防止大量怪物命中时声音叠加失真。字体优先系统中文字体，不强依赖远程字体。

## 12. 性能预算与调试

以下是原型目标，需要在明确的真实测试设备上验证，不是引擎性能保证：桌面浏览器目标 60 FPS，选定中档手机浏览器目标稳定 30 FPS 以上。

| 对象 | 初始同时存在预算 |
|---|---:|
| 普通敌人 | 120 |
| 玩家与敌方弹道 | 合计 180 |
| 经验等掉落物 | 150，超出时合并相近经验 |
| 临时战斗特效 | 60 |
| 伤害数字 | 30，可关闭或聚合同类伤害 |

怪物、弹道、经验、伤害数字与短效特效使用对象池。范围查询使用均匀空间网格，避免子弹逐个遍历所有怪物。Boss 战使用独立预算，低帧率时优先减少装饰特效，不改变伤害和危险预警。

开发调试面板显示 FPS、帧耗时、怪物/弹道/掉落数量、对象池数量、运行时间、玩家属性和装备 ID；支持快速升级、生成指定装备、切换朝向与跳到 Boss。发布版本关闭调试入口。

## 13. 开发里程碑

每个里程碑均应交付可运行版本，按验收通过顺序推进；不在设备和工程环境未确认前承诺工期。

| 阶段 | 交付内容 | 完成标准 |
|---|---|---|
| M0 工程与视觉样机 | LayaAir 工程、横屏布局、斜视地图、几何角色、输入与相机 | 电脑和手机可移动，输入方向与屏幕一致，遮挡正常 |
| M1 可见换装样机 | 四槽、12 件外观、四向显示、前后预览 | 每件装备可独立穿卸，动作中挂点和层级正确 |
| M2 战斗闭环 | 三武器、三普通怪、伤害、经验、升级三选一 | 能连续战斗、升级、死亡并重开，三武器打法不同 |
| M3 装备与构筑 | 掉落、品质、对比、分解、属性重算、专属强化 | 换装同时改变外观和战斗行为，暂停与队列正确 |
| M4 完整一局 | 10 分钟波次、精英、Boss、结算、本地战绩 | 可以从标题完整走到胜利或失败后重开 |
| M5 打磨与适配 | 音效、反馈、真机性能、安全区、稳定性修复 | 通过下方验收清单并记录目标设备测试结果 |

M1 提前实施，以尽早验证用户最关心的可见换装；此阶段装备可由调试菜单切换，不必先实现掉落系统。

## 14. 第一版验收标准

### 玩法

- [ ] 无外部素材下载也能运行完整一局。
- [ ] 三种武器均能单独完成一局，具有不同攻击形态。
- [ ] 普通怪、精英与 Boss 的危险攻击可识别、可躲避。
- [ ] 升级三选一无重复项、无满级无效项，专属强化正确受武器约束。
- [ ] 死亡、胜利、超时、主动退出均有明确结果，重开不残留上一局状态。

### 装备与外观

- [ ] 四个槽位、12 件装备均可获得和穿戴，具有可辨认外观。
- [ ] 四个方向下武器、头饰、护甲和背饰的挂点、显隐、遮挡正确。
- [ ] 移动、冲刺、受击和死亡时装备跟随角色，弹道从正确挂点发出。
- [ ] 品质改变数值和局部装饰，不破坏装备类别辨识。
- [ ] 装备对比预览与战斗中实际外观一致；预览不产生真实伤害。
- [ ] 连续换装不会叠加旧属性、免费回血或残留旧武器特效。
- [ ] 覆盖 3 武器 × 2 头饰状态 × 2 护甲状态 × 2 背饰状态 × 4 朝向的基础组合检查；其余单件外观逐项检查。

### 稳定性与性能

- [ ] 暂停、升级和换装期间所有战斗计时均停止，多弹窗连续处理正确。
- [ ] 浏览器切后台后不会继续掉血，回到前台可正常继续。
- [ ] 至少在一台桌面设备与一台明确型号的手机上完成 10 分钟实测。
- [ ] 达到对象预算时不会无上限生成；经验合并不丢失总量。
- [ ] 连续重开 5 局后，监听器、计时器、对象池与缓存无持续异常增长。
- [ ] 无阻断流程的报错；关闭音效、震动后设置正确保存。

实现期间优先为伤害计算、品质倍率、换装属性重算、专属强化筛选、暂停队列编写针对性自动测试；视觉层级、手机操作与性能通过运行时检查验证。

## 15. 后续扩展顺序

首版通过后，优先根据试玩反馈改善战斗手感与装备辨识，再考虑增加新武器和装备。之后可逐步加入房间探索、更多角色、局外内容解锁和正式美术。保留四槽分层换装接口，避免后续更换资源时重写装备系统。

本方案的首个可交付物是：玩家在斜视竞技场内移动，通过调试入口更换四类装备，并能从角色身上直接看出变化。它同时验证技术路线、几何风格和可见换装的可行性。
