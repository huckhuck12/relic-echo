# 0.13.4 冰环扫掠与雷丸选敌

本轮修正实际命中路径，未修改伤害倍率、成长门槛、掉率或叠层阈值。沿用 RPG skill 的成长与组合验证思路，在现有 Laya 运行时中实现。

## 实装

- 冰环此前每 0.35 秒只检查两个瞬时位置，旋转在两次检查之间扫过敌人时会漏碰撞。现在每步沿旋转与玩家平移形成的路径检测，以不大于 0.15 弧度的短弦近似圆弧，误差补偿小于 0.26 世界单位，避免把新中心的整片圆盘算作命中。
- 每个环绕释放对每个敌人保留 0.35 秒接触冷却；两枚环绕物共享记录。记录最多 600 个目标，死亡或冷却结束后清理，满额时拒绝新接触，不能绕过冷却；释放结束或清场后可随效果对象回收。一次更新最多处理剩余寿命内的路径，正常三秒环绕最多 120 段。
- 雷丸优先瞄准 500 范围内存活、印记未过期且未锁定的敌人，印记更多者优先，同优先级取最近；没有可接续印记时取最近存活敌人。其他弹丸也使用最近目标，不再受空间网格枚举顺序影响。
- 弹丸结算改为弹道最早进入命中圆的敌人。仍是直线弹道，沿途敌人可以拦截；选敌本身不加印、不穿透、不追踪。

## 同种子整局回归

命令：npm run check:balance -- --seeds=627 --weapons=storm,flame,blade。另运行同种子雷杖六分支 --normal。前版使用已提交的 0.13.3 after 数据；[精简对照数据](data/build-playtest-0134.json)保留每局伤害、成长时间、受击与致命暴露。

以下为保命压测整场的碎裂/雷爆次数，0.13.3 → 0.13.4：

| 分支 | 雷杖 | 炎炮 | 环刃 |
|---|---|---|---|
| 碎冰 | 0 → 11 | 1 → 13 | 1 → 6 |
| 寒牢 | 1 → 7 | 0 → 5 | 0 → 2 |
| 传印 | 3 → 5 | 1 → 2 | 2 → 6 |
| 蓄雷 | 0 → 2 | 0 → 1 | 1 → 2 |

火焰六局反应和伤害与前版一致。冰霜六局碎裂共 3 → 44，雷电六局雷爆共 7 → 18。18 局保命样本均覆盖并击败 Boss，但保命规则阻止死亡，不能视为通关率。战斗变化会改变随机数消耗路径，单种子不足以证明统计平衡或单项因果效果。

六局普通雷杖样本均正常死亡，时长 231.27–289.38 秒；碎冰/寒牢各兑现五次碎裂，传印一次雷爆、蓄雷零次。雷电在普通怪潮阶段仍难兑现，后续应拆分武器击退、目标存活时间、导冷覆盖和叠印窗口，而不是据保命 Boss 样本宣称已平衡。

## 验证与限制

- 287 项测试通过，新增七项覆盖漏采样、30/60/120 Hz 与长步进、移动中心、接触上限、选敌和最早碰撞。
- H5 393×852、852×393、1280×720 的真实浏览器触控与渲染回归通过。
- 首次 CI 暴露浏览器测试时序冲突：软件渲染截图耗时期间自然奖励可能先打开，人工升级卡被排队后测试却立即查找它。人工卡片阶段现在独立暂停战斗并清理先前弹窗，保留真实触控、排队领取和令牌校验；正式游戏流程不变。
- Node 进化专项 240/600/1000 敌人、三武器各 300 个采样；1000 敌人逻辑 p95 为 4.841/5.991/5.203 ms，冰层记录上限 200。存在 GC/调度尖峰；这是桌面 Node + 空绘图，不能换算为 iPhone FPS、GPU 或热机结果。
- 微信 SDK 模拟回归通过，本地 _wechat 为 0.13.4，包体 3,936,867 字节，低于 4 MiB，并保留本地 AppID。没有新增图片或 GPU 图集；iPhone Air 的长局热机、触控与直接退出微信仍需真机复验。
