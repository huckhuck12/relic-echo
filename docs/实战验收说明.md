# 实战验收

运行 `npm run dev`，打开 <http://localhost:8080/bench/acceptance.html>。这是独立开发入口，正式游戏入口不变。

## 操作步骤

正式游戏也可直接看局内性能面板：按 P 或暂停菜单切换，默认开启。观察 FPS、帧间隔/P95、更新/绘图 CPU 时间和实体数量；窗口变化或暂停后重新积累至少 5 秒。绘图时间只计 Game.render，不等于本页包装 Laya.stage._loop 的完整引擎 CPU 指标，两者不可直接混用。

1. 分别选择雷杖、炎炮、环刃，先验收 240 怪，再检查 600 怪；1000 怪仅作压力档。每次更改下拉框后点击“重建场景”。场景使用无敌玩家、高生命怪物、满级装备与强化，包含 170 个掉落和初始弹幕，用于保持负载，不代表正常局难度。
2. 收起验收面板，移动、冲刺，观察紫色法师出手挂载、橙色冲锋预警层级、玩家和掉落的辨识度。确认后再勾选相应项目。可对照 `/bench/enemy-effects.html` 慢看独立动作。
3. 点击“检查选卡恢复”：程序触发真实升级，检查模拟暂停，通过正式 Laya 卡片按钮事件完成选择，再检查模拟是否恢复。自动选择不能代替人工点击、触屏命中与焦点切换验收，这些仍需手动验证。
4. 调整为桌面、手机竖屏和横屏窗口，检查 HUD、卡片、触控区域、鼠标落点与遮挡。调整尺寸会清空当前性能样本和人工勾选，需要重新确认。桌面窄窗口不能代替手机真机。
5. 保持页面前台运行至少 5 秒，再导出 JSON。每次重建保存上一组场景的报告；导出包含历史场景、当前场景、运行错误、选卡结果和人工确认项。

## 数据边界

- 帧间隔取前台、战斗未暂停时最近 300 帧的 `requestAnimationFrame` 间隔，展示均值、P50、P95、最大值与估算 FPS。暂停、切后台或改变窗口尺寸后重新采样。
- 舞台耗时包裹正式 `Laya.stage._loop`，记录引擎 CPU 工作，不是 GPU 执行时间，也不能与帧间隔直接相加。游戏仍运行正式固定步循环。
- 报告记录实际怪物数、可见怪物数、窗口尺寸、画质与浏览器公开的渲染器。负载随战斗改变；对比时需保持机器、浏览器、画质、窗口和采样时长一致。
- 未勾选的画面项目标记为“待人工验收”，不会自动判定通过。选卡检查中切后台会报告未完成，需要回前台重试。
