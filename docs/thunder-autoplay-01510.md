# 0.15.10 指定自动试玩、弹窗动效与蓄雷续存

## 游戏内测试入口

主菜单「自动试玩设置」，或暂停页停止当前自动测试后进入同名入口：

- 构筑：全部六分支轮换，或固定火径、炉心、碎冰、寒牢、传印、蓄雷之一。
- 武器：全部三武器轮换，或固定雷杖、炎炮、御刃。点按对应行切换。
- 时长：快速探索 6 分钟 / 标准探索 12 分钟。
- 启动：正常试玩会扣血和死亡；保命压测的致命伤保留 1 血。两者均开启新局、不计战绩。

指定分支仍通过真实奖励选择起始搭配和分支，碎片按原规则获得，不直接授予满级。结算重开保持固定选择；只固定分支时轮换三武器，只固定武器时每局切换下一分支，默认保留六分支×三武器的十八局轮换。暂停页显示实际计划分支与轮换方式；报告 `selection` 记录分支与是否轮换武器，实际配方/等级仍单独记录。

设置页返回不改变当前局；设置过程中不推进自动操作。布局覆盖 320×568、393×852、568×320、852×393、1280×720，所有操作目标至少 44×44。当前仅指定六条预设成长路线，尚不支持任意三碎片配方或强制满级局。

脚本也可筛选，例如：

```powershell
npm run build
node scripts/check-build-balance.mjs --mode=standard --branches=charge --weapons=storm --seeds=627 --normal
```

去掉 `--normal` 为保命逻辑压测；`--branches` 支持逗号分隔。

## 弹窗反馈

沿用 game-ui-ux 与 game-feel skill 的触控、事件反馈原则。新弹窗/设置子页以 180ms 缓出曲线淡入，遮罩从 0.68 渐至 0.9，纸面上浮 6px、从 1.012 倍收拢到 1 倍。开场缩放不小于 1，按钮从出现起可点；不延迟奖励回调，不增加滤镜、粒子或第二条动画循环。

同一弹窗内切选项/重排不会重新播放；切换实际奖励令牌时播放下一次。销毁/重排先取消旧动画，切后台直接归位，浏览器启用减少动态效果时跳过（微信端尚未读取系统此项偏好）。沿用现有整卡点击、暂停与摇杆节点，不改变触摸所有权。这里只增加进入动效，尚未制作退出动画或全套 UI 美术替换。

## 雷电定位与规则

0.15.9 种子 627、三武器、两条雷电分支的保命跟踪中，蓄雷雷丸有效接触分别为 86/92/146 次，存活并可叠印的仅 39/38/62 次。清理时一层目标死亡分别 31/33/48 个。Boss 身上常见三、四印耗尽首印起的九秒窗口，例如风暴 602.5s 第一印、609.0s 第三印，612.1s 已重新起叠；御刃 609.6s 到四印，613.1s 又回一印。

本轮没有直接提高伤害或降低五印门槛：

- 雷电弹丸有限追踪释放时选择的活目标，最大转向 8rad/s，速度和寿命保留；目标死亡后沿当前方向飞，不重新搜敌，沿途仍可能被其他活目标挡住。火/冰/冲击弹丸继续使用原弹道。
- 蓄雷的雷丸直接命中将存续时间设为九秒。导冷仍只在直接命中时额外贡献一印，冷却一秒；传播/元素连锁不能单独续期或引爆。爆发锁一秒、预算不足不消费印记等规则保留。
- 追踪关系用弱键表绑定弹丸，不进入伤害或显示快照；无逐帧全范围索敌、额外定时器或无限对象列表。

## 相同样本对照

仍使用标准模式、真实奖励与自动走位。正常种子 627/1104 × 三武器 × 六分支 36 局，保命种子 627 × 三武器 × 六分支 18 局。下表比较 0.15.9 与 0.15.10：

| 模式 | 分支 | 引爆局数：前→后 | Buff 有效伤害占比中位数：前→后 |
|---|---|---|---|
| 正常 | 传印 | 0/6 → 0/6 | 4.69% → 4.20% |
| 正常 | 蓄雷 | 0/6 → 0/6 | 4.69% → 4.20% |
| 保命 | 传印 | 3/3 → 3/3 | 7.66% → 5.95% |
| 保命 | 蓄雷 | 0/3 → 3/3 | 7.64% → 5.98% |

保命蓄雷三武器分别引爆 2/1/2 次，首爆约 610.1/611.0/610.4 秒；传印分别 4/1/3 次。火焰与冰霜数据保持 0.15.9 的结果。正常仍只有一局炉心完成 Boss，保命 18 局均完成 Boss。

改善的是 Boss 阶段连续叠印可兑现性，普通怪阶段尚未解决，伤害占比也没有普遍提高。不同战斗会改变随机数消耗和掉落，不能由这组样本单独分离追踪、续存与成长路径的贡献，也不能当作真人胜率或 iPhone 性能。逐局数据见[结果 JSON](data/build-thunder-01510.json)，对照见[0.15.9](frost-contact-0159.md)。

复现完整样本：

```powershell
npm run build
node scripts/check-build-balance.mjs --mode=standard --normal --seeds=627,1104 --weapons=storm,flame,blade --out=artifacts/build-normal-01510.json
node scripts/check-build-balance.mjs --mode=standard --seeds=627 --weapons=storm,flame,blade --out=artifacts/build-protected-01510.json
node scripts/summarize-build-balance.mjs artifacts/build-normal-01510.json artifacts/build-protected-01510.json --out=artifacts/build-thunder-01510.json
```

## 待办

普通怪阶段仍需解决叠印投入经常随死亡丢失的问题。下一批表现包含玩家与敌方，继续共用图集和特效预算：

- 玩家雷杖：明确电束主干、分叉电弧和短暂命中余辉，避免长时间遮住目标。
- 玩家炎炮：区分火球暖芯、短尾迹、爆破与余烬，压低重复烟雾和透明覆盖。
- 玩家御刃：强化飞刃方向、挥斩弧和命中切痕，使实际路径与伤害范围易读。
- Buff：保留与武器不同的轮廓、触发节奏和区域提示；两槽同时触发时仍能辨认来源。
- 敌方：区分远程怪/精英/Boss 的弹头、尾迹与命中/消散；危险信息优先于装饰。

验收使用相同种子与密度比较 DC、纹理内存、帧时间和重叠可读性，再复测 iPhone Air 长局；不以增加粒子数量作为效果升级。地图四封印应从相同守圈机制发展成不同目标、地形取舍与怪潮节奏，再完善区域美术。本版未实现这些内容。
