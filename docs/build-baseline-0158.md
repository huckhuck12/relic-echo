# 0.15.8 Buff 构筑统计与基线

本轮使用 RPG skill 的成长、取舍与验证思路，在当前 Laya 实时战斗中统一试玩统计。建立可复查基线，未调整伤害倍率、叠层门槛、掉率、成长速度或敌人压力。

## 实装

- 自动试玩报告升级为 schema 4，记录首套双槽搭配、首个活跃分支、首个活跃配对满级、首次观察到进化的局内时间；未发生保持 `null`。成长/进化按现有 150ms 决策间隔观察，选择奖励后立即检查；火焰连线形成即视为进化出现，不能据此推断连线已经命中。
- 全场与 Boss 分别记录武器、Buff 行为/元素、反伤等来源的有效伤害、Buff 占比。使用与伤害排行相同的唯一扣血事件，排除溢出和尸体补伤。旧 Node 脚本原先包裹回调时没有转发新参数，现已修正并校验各项总额一致。
- 受击记录区分实际扣血、接受的伤害次数和致命暴露。无敌与训练伤害不计；保命模式只剩 1 血时，实际扣血可以为零，但致命暴露继续累计。
- Boss 出场与击杀由真实事件记录。只有实际击杀才产生 `killSeconds`；未击杀保持 `null`，另用 `observedSeconds` 表达暴露时长，避免把超时或死亡当作击杀耗时。
- 开启自动试玩才收集这些战斗统计。每 10 秒、结束与停止时保存到本机；最多保留 18 局结算，序列化超过 65536 字符时先移除最旧记录。保留最新结果，存储失败不打断游戏；微信「暂停 → 复制运行诊断」可导出 schema 4 报告，无自动上传。

## 下一步的具体优先级

1. 冰霜：优先检查「释放 → 环绕接触 → 同目标叠层 → 手动/自然碎裂」链路。正常样本的 Buff 伤害仅约 1%，寒牢在 9 个正常与保命样本中均没有碎裂；需要区分自动走位、武器提前击杀、命中与跨槽冲击的影响。
2. 雷电：检查雷丸连续命中同目标、导冷覆盖与叠印兑现。传印在普通怪潮中几乎不引爆，蓄雷在这些样本中完全未引爆。先让成长后的机制能稳定使用，再校准分支伤害差异。
3. 真人生存与成长节奏：正常 36 局仅 3 局到达 Boss、无击杀，而保命 18 局均击杀。应独立评估走位策略与压力曲线；保命通关不能解释为真人胜率或构筑已平衡。

这些是定位线索，尚不能证明具体机制的因果关系。不同构筑的战斗会改变随机数消耗，同种子并不保证后续掉落与敌人完全相同；少量种子和自动走位不能代替真人玩法判断。
