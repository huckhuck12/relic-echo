# 微信小游戏接入 · 0.11.3

当前完成双端平台接口与最小游戏代码包。默认构建保留占位 AppID；本地开发者工具与体验版已开始真机测试，iPhone Air 的进程退出问题仍在排查。

## 体验版闪退后的诊断

0.11.2 在引擎加载前注册微信脚本错误、未处理 Promise 拒绝及内存告警回调；初始化后每 10 秒保存局内时间、实体数量和帧统计，并记录 Laya 自己计入的 CPU/GPU 资源量。后者不是微信进程总内存，也不是实际 GPU 总占用。

记录只存本机，不自动上传；只保留本次与上次运行，每次最多 12 份周期摘要和 8 条事件，序列化记录最多 32768 字符。报错文本截断，存储失败不影响游戏。

如果整个微信退出，重新打开同一体验版，开始游戏后点暂停 → **复制运行诊断**，将剪贴板文本提供给开发者。不要先清除小游戏数据，否则上次记录也会消失。系统/原生层终止不保证触发 JS 错误或内存告警；没有错误事件不能排除内存压力，最近一次摘要也可能早于退出约 10 秒。

程序音效同时连接最多 8 组振荡器/增益节点，结束、失败、切后台时显式断开；无 ended 回调时在后续播放按音频时钟回收。此为资源生命周期修复，尚未证明它是退出根因。

## 生成与导入

使用 Node.js 22+（推荐 24）：

```powershell
npm ci
npm run build:wechat
```

微信开发者工具选择“小游戏”，导入生成的 `E:\devtools\xxgame\_wechat` 目录。不要导入源码目录 `wechat` 或 H5 的 `_site`。`project.config.json` 默认是占位 `touristappid`，不能据此完成真实 AppID 的预览、上传和发布；工具对游客项目的支持以当前工具为准。

拿到小游戏 AppID 后可在 PowerShell 构建时指定：

```powershell
$env:WECHAT_APPID = 'wx0123456789abcdef' # 替换为自己的真实小游戏 AppID
npm run build:wechat
```

输出目录是可删除重建的产物，每次构建会覆盖；持久的 AppID 配置放在环境变量中。首版固定竖屏；没有服务端、登录、排行榜或广告。微信端关闭测试复活，倒下直接结算；H5 保留现有开发测试复活。支持微信 WebAudio 时使用程序音效，不支持或 SDK 返回异常时静音继续。

## 目录和启动顺序

```text
_wechat/
  game.js                 微信入口
  game.json               竖屏配置
  project.config.json     工具项目配置与 AppID
  engine-environment.js   项目维护的旧引擎环境桥接
  engine.js               固定版 core + webgl + wxmini，原引擎源码不改写
  app/                    TypeScript 编译的 CommonJS 游戏模块
  LICENSE-LayaAir.txt      官方 MIT 许可证
  manifest.json           版本、文件清单与构建体积
```

先创建主屏 Canvas 和引擎需要的环境，再加载引擎与适配库，安装微信平台实现，最后启动 Game/GameUI。官方类名是 `MiniAdpter`；Laya 的 Browser 初始化时自动启用它，不应在 Browser 初始化前手动 enable 导致递归初始化。

引擎环境保存在 `GameGlobal.__relicEngineWindow`，不覆盖开发者工具宿主的 `window`、`document` 等只读属性；引擎加载后仅将 Laya 导出给游戏模块。更新代码后重新构建并在 `_wechat` 项目中编译，不能直接运行 `wechat` 源码模板。

环境桥接只给自建的模拟节点维护 `parentNode`；原生 Canvas/Image 的父子关系保存在内部映射中，不写入原生只读属性。回归检查包含严格模式下的只读 Canvas，以及挂载、换父节点和移除操作。

微信 SDK 负责主画布铺屏；桥接通过独立的普通 `style` 对象隔离旧引擎的 CSS 缩放，避免 DPR=3 时画面被再次缩至三分之一。布局仍使用逻辑像素，微信端引擎像素比最高 2：393×852 屏幕的缓冲区为 786×1704，较 3 倍分辨率减少约 56% 像素。SDK 原始窗口信息、触点和安全区不改写；限制只作用于传给旧引擎的 SDK 视图。浏览器模拟按 SDK 铺屏方式显示画布，并检查真实 DOM 边界，不能只检查引擎内部宽高。

入口在引擎启动前调用 `wx.setPreferredFramesPerSecond(60)`，每次回前台重新申请；不支持该 API 的环境继续运行。引擎保持 `fast` 模式，不隔帧渲染。60 是请求目标，实际帧率仍取决于宿主调度与 CPU/GPU 负载，不能据此宣称稳定 60 帧。开发者工具的帧率需要与微信真机分别测量；游戏性能面板显示实际战斗帧间隔、P95 与更新/绘图指令耗时，模拟环境报告也记录这些采样，后两项不包含引擎提交和 GPU 时间。

旧引擎直接引用的 `CanvasRenderingContext2D`、`ImageData` 和 `performance` 绑定到该独立环境：2D 原型与像素数据由微信 Canvas 提供，时钟统一为毫秒。浏览器回归屏蔽这些宿主全局对象，避免浏览器替微信提供缺失能力。构建保留 `_wechat` 根目录及开发者工具的 `project.private.config.json`，支持项目打开时重新生成代码。

适配库来自官方 LayaAir-v1 的 master2.0 历史分支，当前 core 与该修订原文件哈希一致。构建会校验三份引擎库的规范化哈希，换引擎版本必须重新验证适配器。来源和许可证见 `vendor/README.md`。

`platform/runtime.ts` 为业务提供屏幕、安全区、触控能力、字体、时钟、存储、生命周期和音频。浏览器实现使用 DOM；微信实现使用 wx API。微信前后台切换释放输入、暂停并重置帧时钟，回前台不会自动解除战斗暂停。UI 同时避开设备安全区与右上角胶囊。取消复活请求使用项目自己的最小取消信号，避免依赖小游戏未必具有的 DOM AbortController。

## 验证边界

```powershell
npm test
npm run check:mobile
npm run check:wechat
```

`check:wechat` 执行生成包和真实 Laya/WebGL，以模拟 wx API 驱动主屏 Canvas、触点、存储和生命周期；检查设备 DPR=3/渲染上限 2、胶囊避让、开局推进、双指摇杆/冲刺、触点取消、前后台暂停、连续回血奖励和禁用测试复活。奖励期间仍按住的左指保留身份但不移动，最后一张卡后继续；飘字/怪潮提示不命中，选卡后重新落指仍可在底盘外激活浮动摇杆。失焦、暂停、旋转和换局仍清除触点。截图与报告位于 `artifacts/mobile-check-*`。这不是微信开发者工具或真机验收。

密集战斗诊断：先构建 H5 和微信包，再运行 `node scripts/check-mobile-browser.mjs --wechat --stress`。使用相同种子生成 202 怪物、206 初始弹道和 103 掉落，交替比较向量怪物与共享图集的真实引擎开销，结果写入 `wechat-stress.json`，并保存同一场景两种绘制方式的截图。正式代码启用静态地面的 normal 缓存，普通怪物共用一张 1024×1024 图集（固定 4 MiB，57 个动作/颜色帧），不为每只动态怪物创建 Canvas 或纹理。受击、冰冻和施法动作仍保留；Boss、高画质和图集不可用时走原向量绘制，向量形状缓存最多保留 256 组。

本轮桌面 wx 模拟对照中，DrawCall 约从 746 降至 202，引擎整帧 CPU 均值约从 6.1～6.4 ms 降至 3.3～3.6 ms。该诊断固定每帧一次更新，不能代表真机掉帧时的补步开销，也不能作为 iPhone 帧率保证。性能详情新增每帧补步数、每步更新耗时、引擎等 CPU 与 DrawCall；引擎等 CPU 是公开 `Stage.render` 的墙钟耗时扣除本帧游戏更新和绘图指令生成，仍包含其他定时器和提交等待，不是 GPU 测量。真机下一轮需对比怪多时帧率、补步和引擎等 CPU，并继续检查退出后的本地诊断。

CI 保留 H5 的测试与发布，额外构建微信包、执行上述检查，并在成功后提供 `wechat-minigame` 构建产物供下载。它不会向微信后台上传或发布。

取得真实 AppID 后，需在开发者工具确认控制台无异常，再用 iPhone/Android 验证中文字体、双指触控、刘海/胶囊避让、切后台恢复、存档重进与六分钟完整战斗。需要广告复活时再实现 ReviveProvider，只有完整观看成功才发奖；不要重新启用测试复活冒充广告。
