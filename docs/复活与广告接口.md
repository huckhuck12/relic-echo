# 复活与广告接口 · 0.10.5

当前浏览器版本按钮是「测试复活（未接广告）」，点击直接返回测试奖励。尚未创建广告位、加载 SDK 或展示真实广告。

## 游戏规则

每局真实死亡后提供一次复活；仅成功时消耗次数。恢复最大生命的 50%（向上取整）、冲刺冷却归零、无敌 3 秒，保留局内时间、经验、等级、装备与 Buff 配方/等级。复活清除敌方弹道，取消敌人当前蓄力和冲锋，攻击冷却至少 1.2 秒；150 世界单位内的怪被推开，Boss 血量保留。己方弹道、火焰与 Buff 持续效果保留。死亡前未领取的排队奖励作废。

再次死亡、拒绝复活、主动结束或六分钟超时正常结算。死亡期间暂停战斗；不能通过关闭弹窗绕过。复活后如果存在失焦等暂停原因，显示暂停面板，玩家点击继续才恢复战斗。

## 接入方式

平台启动层在创建 Game 后替换 `game.revival.provider`，实现 `ReviveProvider`（`src/platform/revive-provider.ts`），不向 Game/UI 中直接写入广告 SDK 调用。

| 成员/结果 | 约定 |
|---|---|
| `label` | 正式平台可设为「观看广告复活」，没有广告能力时不能使用此文案 |
| `request(signal)` | 返回 `Promise<ReviveOutcome>`，只在用户点击复活后调用 |
| `rewarded` | SDK 明确确认完整观看并符合奖励条件时返回 |
| `cancelled` | 提前关闭、用户取消；不消耗次数，仍可重试 |
| `failed` | 无填充、加载/播放错误或平台不支持；不消耗次数 |
| `signal.abort` | 玩家离局、重开或等待超过 45 秒；清理监听，允许时关闭广告实例 |

不要把「打开成功」「播放开始」「窗口关闭但无完整观看证明」当作 rewarded。适配器负责将平台 onClose/onError 映射为上述结果，并在所有出口移除监听；同一请求只 resolve 一次。未来可按平台要求调整超时策略。

ReviveService 同时只运行一个请求。Game 的局代号与 downed 校验提供第二层隔离：即使 SDK 忽略取消信号，旧局回调也不能复活新局或已结束的角色。请求失败和取消信息直接显示在复活弹窗，玩家可以重试或结束本局。平台运营配置、防刷与奖励验证需要在正式广告接入时按平台规范实现。

## 已验证范围

自动测试覆盖成功、重复点击、取消、异常、超时、迟到回调、离局重开、广告失焦、二次死亡、拒绝和手机旋转布局；全套 176 项通过。测试使用 Laya 逻辑替身，不代表已经通过真实广告审核、真实 WebGL 性能或真机观看链路验收。
