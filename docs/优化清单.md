## 已落地的措施与边界

- **0.12.0 手绘幻想与五项渲染调整：**地形使用六种重复纹理，石柱保持深度和遮挡透明度；普通怪、常见敌弹/火球、石柱及掉落共用图集，避免深度排序中的纹理切换；玩家只缓存当前装备的 128 个姿势，换装销毁旧纹理；血条背景/填充集中绘制，地面预警保留真实范围与层级。系统衬线标题、暖纸 UI、原创柔和轮廓替换方块表现。默认装备场景纹理标准约 10 MiB，双档均创建约 14 MiB，最坏预算 18 MiB；面板显示场景纹理合计，不能当作进程总内存。216 项回归通过。美术源和预算见[美术规范](手绘幻想美术规范.md)。

同一浏览器冻结场景（精细、235 怪/208 弹/150 掉落、271.5 秒、393×760）从 v0.11.7 的 243 DC 降到 v0.12.0 的 26 DC，前后基线均稳定。新版隐藏地图/柱子减少 2、玩家 2、血条/预警 4、UI 14、Buff 2、飘字 1；怪物和弹道分别隐藏为 0，表示该场景已与保留的其他实体合批，不表示渲染免费。差值不可相加。真机 FPS、热机及微信退出仍待复测。

原始数据见 [render-results-0120.json](render-results-0120.json)。新版美术两轮精细档矢量/图集开关对照，202 怪、206 初始弹道、103 掉落，引擎 CPU 均值分别为 22.83 / 20.18 ms 与 1.62 / 1.61 ms。此项是新版美术的开关实验，不是旧版 CPU 对比；开发机浏览器不能替代真机。

- **0.11.7 DrawCall 拆分：**性能详情“拆分 DC”冻结当前战斗，读取全帧真实批次；10 类内容逐一隐藏对比，前后基线、预热与中位数抑制噪声。分开怪物本体与血条/预警，不重排正式显示树，不强制 flush 破坏合批。显示隐藏该类后的边际差值，不当作独占批次且不可相加；后台/旋转取消并恢复。报告本机持久化并随微信诊断导出。浏览器冻结场景的地图/柱子、怪物本体、弹道差值较大，待真机同场景确认后决定优化顺序。
- **0.11.6 保命压测：**标题“自动压测·保命”或暂停“自动压测新局”，致命伤保留 1 血，受击、反伤和受击 Buff 保持运行；走正常五分钟怪潮与 Boss 时间线并连续换武器重开，不计正式战绩。停止即取消保护。报告区分正常/保命模式，增加是否到达 Boss、Boss 时长及阶段 FPS/P95；入场重置采样窗口。正常自动试玩仍保留，压测结果不能用于判断通关率。
- **0.11.4 自动试玩：**标题或暂停菜单开启，通过正式移动/冲刺/奖励入口驱动，轮换三种武器连续重开，不增加生命或修改难度，不写正式战绩。前台每 150 ms 至多决策一次；手动暂停、失焦和切后台停止操作。保留最近 6 局结果、24 条动作摘要，每 10 秒保存本机报告，随“复制运行诊断”导出。不能验证系统触摸链路，也不保证每局通关；无确定性回放功能。
- **0.11.4 精细图集：**保留精细模型的原始形状、颜色和离散动作，按高度排序装箱，将 57 帧装入 1024×1024 图集。性能面板新增画质、图集是否就绪与总图集内存；失败原因进入本地诊断。
- **0.11.3 共享图集：**三类普通怪共 57 份外观/动作组合，在启动时用相同形状与调色规则生成一张 1024×1024、2 倍采样、无 mipmap 的图集。纹理跨局复用，上传后将临时画布缩为 1×1；高画质及关键敌人沿用矢量。不逐帧上传、不读回 GPU。
- **0.11.3 耗时拆分：**通过公开 Stage.render 采集包含绘制提交与计时任务的 CPU 时间，再扣除同帧游戏更新与绘图指令；记录模拟步数、单步均值和 DrawCall。监控关闭时不计时，不修改引擎私有循环。同步进入原有本地运行摘要。

- **0.11.1 输入修复：**奖励期间保留仍按住的左指，最后一张卡领取后恢复方向；忽略其他手指产生的合成 mouseout；场景和池化飘字不参与触摸命中。失焦、抬指和菜单仍释放输入。
- **0.11.1 渲染优化：**微信引擎渲染像素比上限为 2，缓存静态地面命令，按怪物状态复用有界的形状数据。
- **0.11.2 音频生命周期：**最多同时连接 8 组音效节点，结束、失败和切后台时回收；原生 ended 回调缺失时在后续播放按音频时钟回收。此项尚未证明是闪退根因。
- **0.11.2 排查工具：**启动前注册脚本错误、未处理拒绝及内存告警回调，每 10 秒保存摘要，保留本次与上次运行。暂停菜单可复制诊断；系统/原生终止可能没有回调，Laya 资源计数不等于进程总内存。
- **验证现状：**214 项自动测试通过；H5 与微信真实引擎配合模拟 SDK 的回归通过，包括真实触点启停自动试玩、保命压测、冻结画面 DrawCall 拆分、精细图集及标准/精细的对照压测。这些结果不能代替 iPhone 原生运行验收。

### 真机截图记录（2026-11-02）

来源：用户提供的微信小游戏真机性能面板截图；沿用当前 iPhone Air 测试上下文，截图本身未显示机型、游戏版本、微信/系统版本、画质及热机时长，尚待补齐。

| 指标 | 截图读数 |
|---|---|
| FPS / 平均帧间隔 | 13 FPS / 75.0 ms |
| P95 / 最慢帧 | 81.0 / 82.0 ms |
| 游戏更新 / 绘图指令 | 14.2 / 3.7 ms |
| 怪物 / 弹道 / 掉落 / 效果 | 202 / 206 / 103 / 13 |

采样平均值已严重超出 60 FPS 的 16.67 ms 预算。面板中的更新与绘图指令均值合计约 17.9 ms，与 75.0 ms 帧间隔存在约 57.1 ms 的未覆盖部分；这些均值不等于同一帧的完整 CPU/GPU 时间线，差值只能用于确定下一步采样方向，不能视为实测 GPU 耗时。

`GameLoop` 使用 1/60 秒固定步、每帧最多追赶 6 步；面板更新耗时汇总本帧所有模拟步，不能把 14.2 ms 当成单步耗时。在约 75 ms 帧间隔下可能出现多步追赶，实际步数还受停顿和暂停影响，需要单独记录。

该截图证明了高负载下的性能问题，尚不能解释此前怪物不多时整个微信退出的根因。下一步优先补齐耗时拆分，并用相近实体数量复测；普通怪贴图化作为随后优先对照的渲染方案。

## 执行顺序

先完成闪退排查、摇杆真机复验和性能基线，再按实际瓶颈推进渲染或分配优化，之后集中处理视觉统一。每项记录测试设备、微信/系统版本、游戏版本、画质、复现场景和前后数据；无收益或引入回归的方案撤回。

## 0.12.3：技能与 Buff 视觉统一

已完成：三武器特效、16 种基础 Buff、灼烧/减速与三进化。全档位共用 512² 元素图集，新增 GPU 纹理 1 MiB。地面/上层分别集中绘制，保持伤害边界与角色遮挡。16 Buff 同屏和进化样张 6 DC，武器样张 7 DC；旧版对应为 4/4/6 DC，新增开销是固定绘制层。此为桌面真实 WebGL 样张，不代表 iPhone 帧率。

待验收：iPhone Air 精细画质长时间自动试玩、怪潮/双进化/卡片切换与切后台；继续记录峰值内存、慢帧和闪退。怪物整体美术仍待重画。

## 0.12.4：怪物视觉与图集

五类怪物已重画并接入：史莱姆/野猪四帧、法师手臂与法杖、精英/Boss 双臂、冰冻/受击着色和死亡碎片。164 个合成帧与弹道/掉落/石柱共用 4 MiB GPU 页，三档画质复用同一页；另保留约 4 MiB 解码源图，不能把它当作零内存新增。加载失败保留程序素材，合成失败不会逐帧重试，异步替换会刷新静止实体与场景缓存。

实测桌面真实 WebGL：25/100/200/400 只混合普通怪与精英均为 18 DC；微信 SDK 模拟固定场景 235 怪、208 弹道、150 掉落仍为 28 DC，与 0.12.3 一致。234 项测试、横竖屏交互与微信包验证通过。

仍待：iPhone Air 精细画质长时间压测，记录新源图解码内存、慢帧与闪退；怪物独立八向转身及更多关键帧；玩家步态与场景/UI 深化。本批不能关闭真机闪退问题。
